## Redis

Redis(Remote Dictionary Server)는 데이터를 메모리에 저장하여 빠르게 읽고 쓸 수 있게하는 **인메모리 데이터 저장소**이다.

데이터를 저장하는 거면, MySQL도 있는데 왜 굳이 사용해야하나 싶지만 Redis는 목적이 조금 다르다.

MySQL이 데이터를 안전하게 보관하는 창고라면, Redis는 자주 사용하는 데이터를 가까이에 꺼내 놓는 책상과 비슷하다.

Redis는 데이터를 사전 형태와 비슷한 Key-Value 구조로 저장한다.

```text
Key                         Value
user:name:1                 임승제
email-code:user@test.com    123456
refresh-token:user-1        암호화된 토큰
```

이런식으로 저장되며 원하는 데이터를 찾으려면 Key를 사용하면 된다.

```text
SET user:name:1 "임승제"
GET user:name:1

결과 : 임승제
```

`user:name:1`이라는 이름으로 저장된 값을 달라는 의미이다.

반면 MySQL에서는 테이블과 조건을 이용하여 데이터를 찾는다.

```sql
SELECT name
FROM user
WHERE user_id = 1;
```

## Redis vs MySQL

| 구분 | Redis | MySQL |
|---|---|---|
| 저장 위치 | 주로 메모리 | 주로 디스크 |
| 데이터 형태 | Key-Value | 테이블과 행 |
| 속도 | 매우 빠름 | 상대적으로 느림 |
| 주요 용도 | 캐시, 인증번호, 세션 | 회원, 게시글, 주문 |
| 자동 만료 | 가능 | 일반적으로 직접 처리 |

컴퓨터에는 크게 메모리와 디스크가 있다.

메모리(RAM)는 빠르고 비교적 저장 공간이 작으며 기본적으로 휘발성이다.
디스크는 메모리보다는 느리지만, 저장 공간이 크고 전원이 꺼져도 데이터가 남는다(비휘발성)

MySQL 같은 데이터베이스는 주로 디스크에 데이터를 저장하지만, Redis는 데이터를 메모리에 저장한다. 그래서 데이터를 읽고 쓰는 속도가 매우 빠르다.

자주 사용하는 물건은 서랍에 넣지 않고 책상 위에 꺼내두는 것이 빠른것처럼 Redis도 자주 조회되는 데이터를 메모리에 저장해 빠르게 제공한다.

회원이나 게시글처럼 반드시 보관해야 하는 데이터는 MySQL에 저장하고 인증번호처럼 잠시만 필요하거나 자주 조회하는 데이터는 Redis에 저장하는 것이다.

Redis는 MySQL을 대체하기보다 MySQL과 함께 사용하는 경우가 많다.

## Cache?

Redis의 대표적인 사용 목적은 캐시다.
캐시는 자주 사용하는 데이터를 임시로 저장하는 공간이다. 
예를 들어 사용자 정보를 요청할 때마다 MySQL을 조회하면 같은 작업이 계속 반복되니까 비효율적이다..이때 조회 결과를 Redis에 저장해두면 다음 요청부터는 Redis에서 빠르게 가져올 수 있다.

첫 번째 요청
→ Redis에 데이터 없음(Cache Miss)
→ MySQL에서 조회
→ 결과를 Redis에 저장
→ 결과 반환

두 번째 요청
→ Redis에 데이터 있음(Cache Hit)
→ 바로 결과 반환

Redis에 데이터가 있으면 Cache Hit, 없으면 Cache Miss라고 한다.
이런식으로 Redis를 사용하면 응답 속도가 빨라지고 MySQL의 부담 또한 줄어든다.

## TTL?

TTL(Time To Live)은 데이터가 유지되는 시간을 의미한다. 
쉽게 말해 데이터의 유효기간이다.

```text
SET email-code:user@test.com "593821" EX 180 
```

이메일 인증번호를 3분 동안 유지하고 싶다는 의미다. (EX 180이 데이터를 180초 동안 유지한다는 의미)

**인증번호 저장 → 180초 동안 유지 → 시간 만료 → Redis에서 자동 삭제**

이런식으로 인증번호, 로그인 세션, Refresh Token처럼 유효기간이 있는 데이터를 관리할 때 유용하다.

## Spring, NestJS에서 사용

Spring Boot에서는 주로 Spring Data Redis를 사용한다.

RedisTemplate을 통해 Redis에 데이터를 직접 저장하거나 조회할 수 있고 캐시를 사용할 때는 @Cacheable, @CacheEvict 같은 어노테이션을 사용할 수도 있다.

```java
@Cacheable(cacheNames = "users", key = "#userId")
public User findUser(Long userId) {
    return userRepository.findById(userId);
}
```

반면 NestJS에서는 주로 ioredis나 redis 라이브러리를 사용한다. Redis 클라이언트를 서비스에 주입한 뒤 async/await를 이용해 데이터를 직접 저장하고 조회한다.

```typescript
await redis.set('user:1', '임승제', 'EX', 600);

const user = await redis.get('user:1');
```

사용 방식은 조금 다르지만 두 프레임워크 모두 같은 Redis 명령을 실행하는 것이다.

## Redis는 어디에 사용?

Redis는 빠른 조회가 필요하거나 일정 시간이 지나면 사라져도 되는 데이터에 주로 사용한다.

- 자주 조회되는 데이터 캐싱
- 이메일이나 문자 인증번호
- 로그인 세션, Refresh Token
- 게시글 조회 수
- 실시간 인기 검색어나 순위
- 일정 시간 동안의 요청 횟수 제한

회원이나 게시글처럼 반드시 보관해야 하는 데이터는 MySQL에 저장한다. 반면 이메일 인증번호나 캐시처럼 일시적으로 사용하는 데이터는 Redis에 저장할 수 있다.

즉, Redis는 모든 데이터를 영구적으로 보관하기보다 **자주 사용하는 데이터를 빠르게 꺼내거나 일정 시간 동안 임시로 보관하기 위한 저장소**이다.
