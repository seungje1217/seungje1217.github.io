네트워크를 공부하다 보면 IP 주소, 서브넷, NAT 이런 단어들이 계속 나온다.

근데 처음 보면 느낌이 딱 이거다.

“그냥 주소 아닌가…?”

맞다..주소는 맞다.

근데 단순한 주소가 아니라  
**전 세계에서 컴퓨터를 구분하기 위한 규칙**이다.

---

## IP 주소란?

> 네트워크에서 장치를 구분하기 위한 주소

인터넷에서는 수많은 장치가 서로 통신해야 한다.

그래서 각각을 구분할 수 있는 고유한 주소가 필요하고 그게 바로 IP 주소다.

예를 들어 "192.168.0.1" 이런 형태의 숫자가 바로 IP 주소다.

쉽게 보면 집 주소랑 비슷하다.

- 집 주소 → 위치 찾기  
- IP 주소 → 컴퓨터 찾기  

주소가 있어야 정확한 위치로 데이터를 보낼 수 있다.

---

### IP 주소 구조

IP 주소는 그냥 숫자가 아니라 **네트워크 + 호스트**로 나뉜다.

즉,

네트워크 → 어느 그룹인지  
호스트 → 그 안에서 누구인지  

를 의미한다.

예를 들어 "192.168.0.10" 이라면

192.168.0 → 네트워크  
10 → 실제 장치

이렇게 구분된다.

---

### IPv4 vs IPv6

IP 주소에도 종류가 있다.

가장 많이 사용하는 건 IPv4인데 요즘은 IPv6도 같이 사용된다.

#### IPv4 

우리가 흔히 보는 형태다.

192.168.0.1 이렇게 숫자 4개로 이루어져 있는데,

각 숫자는 0 ~ 255 범위를 가지며 총 32비트 구조다.

IPv4는 약 43억 개 정도의 주소를 만들 수 있다.

처음에는 충분해 보였지만 스마트폰, 노트북, IoT 기기..
이런 것들이 폭발적으로 늘어나면서 주소가 부족해지기 시작했다.

#### IPv6

이 문제를 해결하기 위해 등장한 게 IPv6다.

예를 들어

2001:0db8:85a3:0000:0000:8a2e:0370:7334

이렇게 훨씬 길고 복잡한 형태다.

128비트 구조이며 사실상 무한에 가까운 주소 수이다. 또한 NAT 없이도 사용 가능하다는 특징이 있다.

쉽게 설명하면 

IPv4 → 좁은 아파트  
IPv6 → 도시 전체

이 정도 차이라고 보면 된다.

하지만 현실에서는 아직 IPv4를 많이 쓰고 있고  
부족한 주소 문제를 해결하기 위해 다른 방법들이 같이 사용된다.

그래서 등장한 개념이 **서브네팅 (Subnetting)** 이다.

---

## 서브넷 (Subnet)

> 하나의 네트워크 안을 더 작은 네트워크로 나눈 것

IPv4 주소가 부족해지면서 주소를 더 효율적으로 써야 한다는 문제가 생겼다.

그래서 나온 개념이 바로 서브넷(Subnet)이다.

그냥 IPv6 사용하면 되지 왜 이런거를 또 만들었을까,,,?

예를 들어 보자

어떤 회사가 256개의 IP를 할당받았다.

근데 실제로는 50대만 사용한다면?

나머지 200개는 그냥 낭비된다..

“하나를 크게 쓰지 말고, 나눠서 쓰자”

이게 서브넷의 핵심 개념이다.

아까 아파트를 예시로 들었는데 이것도 쉽게 설명해보자.

아파트 한 동이 있다고 하면

- 전체 네트워크 → 101동  
- 서브넷 → 101동 안의 층, 호수

이렇게 나누는 느낌이다.

---

## 서브네팅 (Subnetting)

> 서브넷을 실제로 나누는 과정

서브넷이 “개념”이라면  
서브네팅은 그걸 실제로 나누는 작업이다.

예를 들어 하나의 네트워크를

- 개발팀용 네트워크  
- 마케팅팀용 네트워크  
- 인사팀용 네트워크  

이렇게 나누고 싶다면?

네트워크를 여러 개로 쪼개야 한다

이게 바로 서브네팅이다.

이렇게 나누면 트래픽 감소, 보안 분리, 관리 편리등의 이점이 있다.

즉, 하나로 몰아쓰는 것보다 훨씬 효율적이다.

---

### 서브넷 마스크

> IP 주소에서 네트워크와 호스트를 구분하는 기준

앞에서 IP 주소는 네트워크 + 호스트로 나뉜다고 했다.

근데 여기서 문제가 하나 생긴다.

어디까지가 네트워크고 어디부터가 호스트일까??

이걸 구분해주는 게 바로 **서브넷 마스크**다.

쉽게 말하면 “여기까지는 같은 네트워크야”  
“여기부터는 각각의 장치야”라고 선을 그어주는 기준이다.

그래서 그 선을 어떻게 나눌까??

IP 주소가 있다고 해보자

이 숫자만 보면 어디까지가 네트워크인지..어디부터가 컴퓨터인지 알 수 없다.

그래서 같이 붙는 게 192.168.0.1 / 255.255.255.0 이런 형태다.

어렵게 생각할 필요없다..간단하게 보면

앞쪽은 3칸은 같은 네트워크, 마지막은 각각의 컴퓨터이다.

즉

192.168.0.1  
192.168.0.2  
192.168.0.3  

이런 애들은 전부 같은 네트워크에 있는 거고

192.168.1.10

이건 아예 다른 네트워크다.

서브넷 마스크는 같은 그룹을 어디까지 묶을지 정하는 기준이다.

지금까지 설명한걸 요약하자면

- IP 주소 → 컴퓨터를 구분  
- 서브넷 → 네트워크를 나눈 결과  
- 서브네팅 → 나누는 작업  
- 서브넷 마스크 → 나누는 기준  

이렇게 정리가 된다..

그럼 이제 IPv4 부족 문제는 해결된걸까??

아직 아니다..서브네팅을 해도 결국 전체 IP 개수 자체는 늘어나지 않는다.

나눠서 효율적으로 쓰긴 했지만  근본적인 부족 문제는 그대로다.

그래서 등장한 게 바로 **NAT**다.

---

## NAT (Network Address Translation)

> 내부 IP를 외부 IP로 변환하는 기술

NAT는 말 그대로 내부에서 사용하는 IP를 외부에서 사용할 수 있는 IP로 바꿔주는 기술이다.

이걸 이해하려면 집 네트워크를 생각해보면 쉽다.

집에는 보통 노트북, 스마트폰, 태블릿 등 여러 기기가 있다.

근데 인터넷을 연결하면 공인 IP는 하나만 받는다.

여기서 이상한 점이 생긴다.

기기는 여러 개인데 외부에서는 하나의 IP만 보인다.

이걸 가능하게 해주는 게 NAT다.

### NAT의 동작 방식

집 안에서는 192.168.0.10, 192.168.0.20, 192.168.0.30 이런식으로 각 기기마다 다른 IP를 사용한다.

근데 인터넷으로 나갈 때는 이 모든 요청이 하나의 공인 IP로 바뀐다.

즉, 내부는 여러개의 사설 IP
외부는 하나의 공인 IP

그럼 여기서 또 궁금해진다.

“응답이 돌아올 때 어떻게 다시 원래 기기로 가냐?”

여기서 중요한 게 하나 더 있다.

바로 **포트 번호**다.

### NAT + 포트 (PAT)

NAT는 단순히 IP만 바꾸는 게 아니라 포트 번호까지 같이 사용해서 구분한다.

예를 들어

- 192.168.0.10 → 203.0.113.5:5000  
- 192.168.0.20 → 203.0.113.5:5001  
- 192.168.0.30 → 203.0.113.5:5002  

이렇게 변환된다.

즉 외부에서는 같은 IP지만 포트 번호로 각각의 요청을 구분한다.

그래서 응답이 돌아올 때

- 포트 5000 → 노트북  
- 포트 5001 → 스마트폰  

이렇게 다시 정확하게 전달할 수 있다.

이걸 PAT (Port Address Translation)이라고도 한다.

실제로 우리가 사용하는 NAT는 대부분 이 방식이다.

이걸 쓰는 이유는 명확하다.

IP 부족 문제를 해결하고, 하나의 공인 IP로 여러 기기를 사용할 수 있게 만들고, 내부 네트워크를 외부에서 직접 접근하지 못하게 하는 역할까지 한다.

---

## 전체 흐름

결국 흐름을 보면 이렇게 이어진다.

IP 주소 → 장치 식별  
서브넷 → 네트워크 분리  
서브네팅 → 효율적으로 나누기  
서브넷 마스크 → 나누는 기준  
NAT → 부족한 IP를 실제로 해결하는 방법    

처음에는 각각 따로 노는 개념처럼 보였는데

정리해보면 전부 하나로 이어진다.

결국 IP는 “주소”이고  
서브네팅은 “주소를 나누는 방법”이고  
NAT는 “부족한 주소를 더 쓰는 방법”이다.
