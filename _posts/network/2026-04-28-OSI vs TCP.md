네트워크를 처음 배울 때 제일 많이 헷갈리는 게 이거다.

굳이 왜 나누지?

솔직히 처음에는  
그냥 하나로 처리하면 안 되나 싶다..

근데 이걸 이해하려면  
전체 과정을 한 번에 보는 게 아니라  
**단계를 나눠서 처리하는 이유**를 먼저 봐야 한다.

---

## 왜 계층으로 나누는 걸까?

이걸 쉽게 생각해보면 “택배”랑 비슷하다.

택배 하나 보내는 과정도 보면

- 물건 포장  
- 주소 작성  
- 배송 처리  
- 이동  
- 전달  

이렇게 단계가 나눠져 있다.


이걸 한 사람이 전부 처리하면 비효율적이다.

그래서 역할을 나누는 거다.

네트워크도 똑같다.

데이터를 보내는 과정이 너무 복잡하기 때문에  
각 역할을 나눠서 처리한다.

이게 바로 **계층 구조**다.

---

## OSI 7계층

> 네트워크 동작을 7단계로 나눈 표준 모델

Open Systems Interconnection

OSI 모델은 “이론적으로 완벽하게 나눈 구조”다.

각 단계가 하는 일이 굉장히 명확하다.

하나씩 알아보자,,

---

### 1계층 (물리 계층 - Physical Layer)

> 실제 신호를 전송하는 단계

우리가 보내는 데이터는 결국 네트워크를 통해 이동해야 하는데,  
컴퓨터는 데이터를 바로 보낼 수 있는 형태로 이해하지 못한다.

그래서 데이터를 전기 신호, 빛 신호 같은 형태로 바꿔서 보내는 역할을 한다.

즉, 데이터 → 0과 1 → 전기 신호 

이렇게 변환해서 케이블을 통해 전달하는 단계다.

물리 계층은 소프트웨어보다는 하드웨어와 직접적으로 연결되어 있다.

예를 들어

- LAN 케이블  
- 광섬유 케이블  
- 허브(Hub)  
- 리피터(Repeater)  

이런 장비들이 전부 물리 계층에 해당한다.


쉽게 말하면 **데이터를 실제로 흘려보내는 통로**를 담당하는 단계다.

물리 계층은 TCP 같은 프로토콜보다는 전송 방식에 대한 규칙(표준)이 중요하다.

대표적으로는

- Ethernet (IEEE 802.3)  
- Wi-Fi (IEEE 802.11)  
- Bluetooth  

같은 것들이 있으며, 이건 “데이터를 어떻게 신호로 바꿔서 보낼지”에 대한 약속이다.

예를 들어

- 전압은 얼마로 할지  
- 신호를 얼마나 빠르게 보낼지  
- 케이블 형태는 어떻게 할지  

이런 것들을 정의한다.

---

### 2계층 (데이터 링크 계층 - Data Link Layer)

> 같은 네트워크 내에서 데이터 전달

물리 계층이 단순히 신호를 보내는 단계라면,  
데이터 링크 계층은 그 신호를 “의미 있는 데이터 단위”로 만들어주는 단계다.

즉, 그냥 흘러가는 0과 1이 아니라 **누가 누구한테 보내는 데이터인지**를 구분해준다.

이때 사용하는 게 바로 **MAC 주소**다.

MAC 주소는 각 장비마다 고유하게 가지고 있는 주소로,  
같은 네트워크 안에서 장치를 구분하는 역할을 한다.

즉, 출발지 MAC → 목적지 MAC  
이 정보를 붙여서 데이터를 전달한다.

스위치(Switch), 네트워크 인터페이스 카드(NIC)같은 장비들이 여기에 해당하며,

관련 프로토콜에는 Ethernet, ARP (IP → MAC 주소 변환)같은 것들이 있다.

데이터 링크 계층에서는 데이터를 **프레임(Frame)**이라는 단위로 나눈다.

그리고 이 프레임에

- 출발지 MAC 주소  
- 목적지 MAC 주소  
- 오류 검출 정보  

같은 것을 함께 담아서 전송한다.

그래서 전송 중 데이터가 깨졌는지도 확인할 수 있다.

---

### 3계층 (네트워크 계층 - Network Layer)

> 목적지까지 경로를 찾는 단계

2계층은 같은 네트워크 안에서만 통신 가능했다.

근데 현실에서는?  
다른 지역, 다른 네트워크로 보내야 한다.

이걸 가능하게 해주는 게 바로 3계층이다.

여기서는 **IP 주소**를 사용한다.

MAC 주소가 “내 근처 장치 주소”라면 IP 주소는 “전 세계에서의 주소”라고 보면 된다.

목적지까지의 경로 결정 (라우팅)과 데이터 전달 역할을 한다.

즉 “어디로 가야 하는지 길을 찾는 단계”다.

라우터(Router)가 여기에 해당되며, 데이터 단위는 패킷(Packet)이다.

관련 프로토콜은 IP, ICMP, 라우팅 프로토콜 (RIP, OSPF 등)이 존재한다.


---

### 4계층 (전송 계층 - Transport Layer)

> 데이터 전달을 안정적으로 관리

3계층이 “어디로 보낼지”라면, 4계층은 “제대로 도착했는지”를 관리한다.

전송 계층에서는 데이터 분할 및 재조립, 오류 제어, 흐름 제어 등의 역할을 한다.

관련 프로토콜은 우리가 많이 들어봤던 TCP, UDP가 여기에 존재한다.

나중에 제대로 설명을 하겠지만, 간단히 짚고 넘어가자면

TCP는

- 연결 기반  
- 신뢰성 보장  
- 느리지만 안전함  

UDP는

- 비연결  
- 빠름  
- 대신 신뢰성 없음 

쉽게 설명하면 TCP는 택배 (확인하고 받음), UDP는 방송 (그냥 보냄)이다.

데이터 단위로는 세그먼트(Segment)가 있으며,

전송 계층의 핵심은 **데이터가 빠짐없이 제대로 도착했는지 관리하는 단계**이다.


---

### 5계층 (세션 계층 - Session Layer)

> 통신을 시작하고 종료하는 단계

4계층까지는 데이터를 잘 보내는 데 집중했다면  
5계층은 “그 통신을 계속 유지할지”를 관리하는 단계다.

이게 왜 필요할까??

예를 들어보자..웹사이트에 로그인해서  
상품을 보고 → 장바구니 담고 → 결제까지 한다고 해보자

이 과정에서 서버는 계속 이렇게 생각해야 한다

“이 사람 아까 로그인한 그 사람 맞지?”

이걸 가능하게 해주는 게 바로 **세션(Session)**이다

연결 시작 (세션 생성), 연결 유지 (같은 사용자로 인식), 연결 종료 (로그아웃)의 역할이 있는데,

쉽게 설명하면 카페에서 자리 잡는 느낌이다.

- 들어가서 자리 잡음 → 세션 생성  
- 앉아서 계속 이용 → 세션 유지  
- 나가면 자리 반납 → 세션 종료  

요즘은 이 기능이 HTTP 쿠키, 토큰(JWT)같은 방식으로 구현되면서
5계층 역할이 7계층으로 올라가버린 느낌이라 딱 분리해서 보기가 애매하다..

그래서 이론에서는 분명 존재하지만  
실무에서는 다른 계층과 섞여서 동작하는 경우가 많다..

핵심은 **지금 이 통신이 누구랑 이어지고 있는지 기억하는 역할**이다.

---

### 6계층 (표현 계층 - Presentation Layer)

> 데이터를 서로 이해할 수 있는 형태로 바꾸는 단계

네트워크에서 데이터를 주고받을 때  
모든 시스템이 같은 방식으로 데이터를 이해하는 건 아니다.

예를 들어

- 어떤 시스템은 UTF-8  
- 어떤 시스템은 ASCII  
- 어떤 곳은 암호화된 데이터  

이런 식으로 형식이 다 다를 수 있다.

그래서 필요한 게 6계층이다.

데이터를 보내기 전에 **상대가 이해할 수 있는 형태로 변환**해주는 역할을 한다.

인코딩 / 디코딩, 암호화 / 복호화, 압축 / 해제의 역할이 있으며,

HTTPS에서 사용하는 SSL/TLS (암호화), UTF-8 같은 문자 인코딩, 이미지 압축 (jpg, png)과 같은 것들이 다 표현계층에 속한다.

쉽게 설명하면 번역기 같은 느낌이다.

한국어로 말했는데 상대가 영어만 알면?

→ 영어로 바꿔줘야 한다..

데이터를 보내는 게 아니라 “형식을 맞춰주는 단계”다.

---

### 7계층 (응용 계층 - Application Layer)

> 사용자가 직접 사용하는 단계

여기까지 올라오면 드디어 우리가 쓰는 영역이다.

브라우저, 앱, 게임, 카톡 이런 것들이 전부 7계층이다.

역할로는 사용자가 데이터를 요청하고 그 결과를 받는 모든 과정이 있으며,

- 웹사이트 접속 → HTTP  
- 파일 다운로드 → FTP  
- 이메일 전송 → SMTP  
- 도메인 찾기 → DNS  

등이 다 여기에 속한다.

맥도날드 키오스크 같은 느낌이다.

우리가 직접 메뉴를 고르고 주문하듯이, 사용자가 직접 요청을 보내는 단계다

여기서 중요한 포인트는 7계층은 “네트워크 내부 처리”를 신경 안 쓴다.

요청 → 응답

이것만 신경 쓴다.

---

## TCP/IP 4계층

> 실제 인터넷에서 사용하는 구조

여기까지 보면 OSI 7계층은 굉장히 잘 나뉘어 있는 구조다.

근데 여기서 한 가지 궁금한 점이 생긴다.

“그래서 이걸 실제로 그대로 쓸까?”

답은 아니다.

실제 인터넷에서는 **TCP/IP 4계층 구조**를 사용한다.

왜냐하면 OSI 7계층은 이론적으로는 완벽하지만  
실제로 구현하기에는 너무 세분화되어 있기 때문이다.

그래서 비슷한 역할끼리 묶어서 단순화한 구조가 TCP/IP다.

---

### 1계층 (네트워크 인터페이스)

OSI 1 + 2계층

물리적인 전송 + 같은 네트워크 내 전달을 담당한다.

즉, 케이블 + MAC 주소까지 포함된 영역이다.


---

### 2계층 (인터넷 계층)

OSI 3계층

IP 기반 주소 관리와 경로 탐색 (라우팅)역할을 한다.

데이터가 어디로 가야 하는지 결정하는 단계다.

---

### 3계층 (전송 계층)

OSI 4계층

TCP / UDP로 데이터 전달을 관리한다.

데이터가 제대로 도착했는지 관리하는 단계다.

---

### 4계층 (응용 계층)

OSI 5 + 6 + 7계층

사용자 요청 처리, 데이터 형식 변환, 연결 유지 영역이다.

우리가 실제로 사용하는 모든 서비스가 여기에 포함된다.

---

## OSI vs TCP/IP 차이

정리하면 이렇게 보면 된다.

OSI는 “잘게 나눈 설명용 구조”  
TCP/IP는 “실제로 사용하는 구조”

좀 더 쉽게 설명하자면

OSI는 설명서  
TCP/IP는 실제 제품

같은 느낌이다.

---

## 흐름으로 이해하기

데이터가 어떻게 이동하는지 보면 이해가 더 쉽다.

사용자가 웹사이트 접속  
→ (응용 계층) 요청 생성  
→ (전송 계층) 데이터 분할  
→ (인터넷 계층) 목적지 설정  
→ (네트워크 인터페이스) 실제 전송  

그리고 반대로 올라오면서 다시 조립된다.

---

## 정리

처음에는 왜 이렇게 복잡하게 나누는지 이해가 안 됐는데

정리해보니까 결국 역할을 나누기 위한 구조였다.


하나로 다 처리하면 복잡해지고 문제가 생겼을 때 원인을 찾기도 어렵다.


계층으로 나누면

- 역할이 명확해지고  
- 유지보수가 쉬워지고  
- 문제 추적도 쉬워진다  


결국 핵심은 하나다.

**복잡한 걸 나눠서 처리하기 위해 만든 구조다.**
