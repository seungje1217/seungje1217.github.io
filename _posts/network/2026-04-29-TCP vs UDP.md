그때는 “데이터를 전달하는 역할” 정도로만 넘어갔는데  
이 부분이 실제 네트워크 동작에서 가장 중요한 역할을 한다.

이번에는 제대로 알아보자.

## TCP vs UDP

> 데이터를 어떻게 보낼지 정하는 방식

같은 데이터를 보내더라도

- 정확하게 보낼지  
- 빠르게 보낼지  

이 선택에 따라 방식이 달라진다.

그걸 담당하는 게 TCP와 UDP다.

---

### TCP (Transmission Control Protocol)

> 느리지만 정확하게 보내는 방식

TCP는 데이터를 보낼 때 상대가 제대로 받았는지를 계속 확인한다.

동작 방식은 단순하다.

1. 데이터 전송  
2. 응답 확인 (ACK)  
3. 문제 있으면 재전송  

그래서 특징은 이렇게 정리된다.

- 연결 기반 (연결 후 통신)  
- 신뢰성 보장 (데이터 유실 없음)  
- 순서 보장  
- 속도는 상대적으로 느림  

쉽게 보면 택배처럼 보냈으면 도착 확인하고 문제 있으면 다시 보내는 방식이다.

TCP는 데이터가 절대 틀리면 안 되는 상황에서 사용된다.

웹사이트 접속 (HTTP / HTTPS)이나 파일 다운로드, 이메일 전송과 같은 상황에서 사용되는데,,

우선 웹페이지를 불러오는 상황을 먼저 생각해보자

HTML 파일은 중간에 하나라도 빠지면 페이지가 아예 깨져버린다. 또한 이미지도 일부만 오면 이상하게 보인다..

파일 다운로드 또한 마찬가지다. 데이터가 하나라도 틀리면 파일 자체가 망가진다.

그래서 TCP는 데이터가 하나라도 빠지면 다시 보내고, 순서도 맞춰서 전달하는 것이다.

---

### UDP (User Datagram Protocol)

> 빠르게 보내지만 확인하지 않는 방식

UDP는 TCP와 반대다..데이터를 그냥 보낸다.

- 확인 없음  
- 재전송 없음  
- 순서 보장 없음  

특징으로는 

- 비연결 방식  
- 빠름  
- 데이터 손실 가능 

이 있다.

UDP는 쉽게 보면 방송 같은 느낌이다.

보냈으면 끝이다. 받았는지 따위는 신경 안 쓴다.

그래서 실시간 스트리밍이나, 온라인 게임, 영상 통화 등에서 사용된다.

왜 이런 서비스에서 UDP를 쓸까?

영상 통화를 예시로 보면 영상 통화는 데이터가 조금 손실되더라도 그냥 다음 화면이 바로 나오는 것이 더 중요하다.

중간에 멈추는 것 보다 족므 깨지더라도 계속 이어지는 게 훨씬 자연스러우니까..

온라인 게임도 비슷하다.

내 캐릭터 위치를 서버에 보내는데, 이전 좌표 하나 유실됐다고 해서 다시 받을 필요는 없다.
어짜피 다음 좌표가 계속 오기 때문이다.

즉 UDP는 데이터가 조금 틀려도 괜찮고  
대신 끊김 없이 빠르게 보내야 하는 상황에서 사용된다.

그럼 TCP는 왜 이렇게까지 느려지면서 굳이 정확하게 보내는 걸까?

단순히 재전송 때문만은 아니다.

데이터를 보내는 방식 자체가 애초에 다르게 설계되어 있기 때문이다.

---

## 흐름 제어 (Flow Control)

> 상대방이 처리할 수 있는 만큼만 보내는 것

TCP는 무조건 데이터를 많이 보낸다고 좋은 게 아니다.

받는 쪽이 처리할 수 있는 속도보다 보내는 쪽이 더 빨리 보내버리면 어떻게 될까?

데이터가 쌓이다가 결국 손실된다.

그래서 필요한 게 흐름 제어다.

쉽게 설명하면 이런 느낌이다.

보내는 쪽 → 계속 보냄  
받는 쪽 → ㄱㄷ 나 지금 처리 중

이걸 맞춰주는 게 흐름 제어다.

TCP에서는 이걸 **윈도우(Window)**라는 개념으로 관리한다.

받는 쪽이 “지금 이 정도까지는 받아도 된다” 라는 크기를 보내주면 그 범위 안에서만 데이터를 전송한다.

즉, 받는 쪽 기준으로 속도를 맞춘다.

그래서 데이터가 넘쳐서 터지는 걸 막는다.

---

## 혼잡 제어 (Congestion Control)

> 네트워크 상황에 맞춰 속도를 조절하는 것

흐름 제어가 “상대방 기준”이라면  
혼잡 제어는 “네트워크 전체 기준”이다.

인터넷은 나 혼자 쓰는 게 아니다..수많은 사람들이 동시에 데이터를 보내고 있을거다.

이 상황에서 다 같이 속도를 올리면 어떻게 될까?

네트워크가 버티질 못하고 패킷이 막히거나 손실될거다.

그래서 TCP는 네트워크 상태를 보면서 속도를 자동으로 조절한다.

문제 없음 → 점점 속도 증가  
패킷 손실 발생 → 속도 확 줄임  

이런 식으로 조절을 하는 , 대표적인 방식으로는 Slow Start (처음에는 천천히 시작), Congestion Avoidance (점점 증가) 이런 흐름으로 동작한다.

쉽게 말하면  길이 막히면 속도를 줄이고, 길이 뚫리면 다시 속도를 올리는 느낌이다.

---

## 흐름 제어 vs 혼잡 제어

정리하면 이렇게 보면 된다.

- 흐름 제어 → 받는 쪽 기준  
- 혼잡 제어 → 네트워크 전체 기준  

TCP가 “느리지만 안정적이다”라는 말의 이유가 바로 이 두 개 때문이다.

- 흐름 제어 → 상대가 감당할 만큼만 보내고  
- 혼잡 제어 → 네트워크 상황 보면서 속도 조절  

이걸 계속 하기 때문에 속도는 느려질 수 있지만 데이터는 안정적으로 전달된다.

반대로 UDP는 이런 과정이 없다.

대신 UDP는 필요한 경우 애플리케이션 레벨에서 직접 제어 로직을 구현한다.

그래서 UDP는 단순하고 빠르지만, 그만큼 책임이 위로 올라간 구조라고 볼 수 있다.
