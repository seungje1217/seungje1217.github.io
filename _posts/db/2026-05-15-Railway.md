이번에 MomFit이라는 졸업 작품을 진행하는 도중,  팀원들끼리 공용 DB를 맞추게 되었다.
<br/><br/>
처음에는 각자 로컬에서 개발을 하고 있었다. Docker로 MySQL을 띄우고, 각자 `.env` 파일에 `localhost`를 넣고 개발하는 구조였다.
<br/><br/>
점점 완성이 되어갈수록 공용 DB의 필요성(게시판 테스트, 로그인 문제 등)을 느끼게 되었지만, 배포 단계는 아니었기 때문에 AWS 같은 정식 배포 환경은 아직 이르다고 판단했다.
<br/><br/>
금액적인 문제도 있기에 무료로 사용할 수 있는 Railway를 선택하였으며, Railway에서 MySQL 인스턴스를 하나 생성하고 그 DB를 팀 공용 개발 DB로 사용하기로 했다.

---

### 왜 공용 DB가 필요했을까?

로컬 DB로 개발할 때는 모든 기능이 정상적으로 동작한다.
<br/><br/>회원가입도 되고, 로그인도 되고, 게시판 글도 잘 저장된다.
<br/><br/>
하지만 문제는 여기서 시작된다.
내가 회원가입을 하면 내 컴퓨터 DB에만 저장된다. 팀원이 같은 계정으로 로그인하려고 하면 존재하지 않는 사용자라고 나온다.
게시판도 마찬가지다. 내가 작성한 글은 나만 볼 수 있다..
<br/><br/>
이 상태에서는 통합 테스트가 불가능하다. 각자 잘 돌아가는 코드가 아니라, 같은 데이터를 바라보는 하나의 시스템이어야 한다.

---

### 환경 분리

로컬 DB를 없앤다는 것이 아니라 환경을 분리하는 것이 중요하다.
AppModule에서 

```ts

ConfigModule.forRoot({

  isGlobal: true,

  envFilePath: `.env.${process.env.NODE_ENV || 'local'}`,

})
```

이런식으로 설정을 하여 실행환겨엥 따라 사용하는 환경 파일을 다르게 만들었다.
<br/><br/>
npm run start로 서버 실행 →  .env.local 파일 사용
NODE_ENV=dev npm run start로 서버 실행 →  .env.dev 파일 사용


---

### Railway 공용 DB 설정

Railway에서 MySQL 인스턴스를 생성하면 접속 정보가 제공된다.  
Host, Port, Username, Password, Database 이름을 확인한 뒤 .env.dev 파일에 입력한다. 이제 공용 DB 모드로 서버를 실행하면 팀원 모두 동일한 DB를 바라보게 된다.
<br/><br/>
처음 공용 DB는 아예 비어있는 상태다. 그래서 seed 작업을 통해 데이터 들을 삽입하였다.
(이 과정에서 외래키 제약 조건 문제와 같은 문제들이 있었지만..잘 해결되었다)
<br/><br/>
덕분에 한 명이 회원가입하면 다른 팀원도 해당 계정으로 로그인할 수 있고, 게시판 글도 서로 공유된다.

---

### 정리 

Railway는 별도의 서버 구축 없이 MySQL 인스턴스를 빠르게 생성해 사용할 수 있는 클라우드 서비스다.
<br/><br/>
배포 단계까지는 아니지만, 팀 단위 개발 환경을 맞추기에는 충분히 효율적인 선택인거같다. 이번 공용 DB 구축을 통해 각자가 아닌 하나의 서비스로 동작하게 되었다.
